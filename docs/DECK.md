# Палуба, помещения и сеть

## Локальное движение

Положение ног каждого участника задаётся в системе координат чертежа. Корпус поворачивает и переносит эту точку в мир. Участники используют один и тот же трансформ корпуса на сервере и каждый раз согласованный с корпусом визуальный трансформ на клиенте. Встроенная связь Minecraft с транспортом управляет жизненным циклом экипажа и списком отслеживаемых сущностей. Пространство ходьбы определяется положением и коллизиями каждого участника.

`DeckMotion` ограничивает перемещение габаритом игрока 0,598 × 1,80 м. Для каждой оси он ищет ближайшую плоскость столкновения на всём пройденном отрезке. Горизонтальные компоненты обрабатываются отдельно, чтобы можно было скользить вдоль стен. Пол держит ноги, потолок ограничивает прыжок. Автоматический подъём на одноярусную ступень использует такую же дугу, как прыжок. Пробоина убирает коллизию повреждённой ячейки, восстановление которой запрещено, пока там находится человек.

Сервер проверяет новое положение также относительно твёрдых блоков мира. При выключенном полёте подходит приземление с пересечением верхней грани палубы. Для посадки правой кнопкой клиент и сервер трассируют видимый корпус и проверяют дистанцию и преграды. При выходе за пределы корпуса игрок переходит к обычному движению с частью инерции судна.

## Управление и синхронизация

С сервером передаются номер входного кадра, направление, локальный угол взгляда и флаги бега, прыжка, пригибания и смены режима. Сервер принимает кадры только от участника этого судна. Он обрабатывает максимум один кадр на игрока в тик. Штурвал доступен одному находящемуся рядом участнику. Без ввода тяга возвращается в нейтраль.

Сервер публикует координаты ног, вертикальную скорость, опору, номер последнего обработанного ввода и идентификатор пилота. Собственный клиент повторяет ещё не подтверждённые входные кадры поверх серверной позиции. Наблюдатель сглаживает движение остальных участников отдельно от интерполяции корпуса. Графический слой использует стоячую модель игрока и анимирует ноги по скорости ходьбы относительно корпуса.

Серверный тик передаёт позицию каждого участника из одного состояния корпуса, без отправки отдельной команды телепортации на каждый шаг. Координаты квантуются с шагом 1/16384 м. Предсказание ограничено четырьмя тиками, 0,82 м по горизонтали и 0,90 м по вертикали. При остановке клиентская позиция сходится с подтверждённой.

Под сплошным перекрытием клиент убирает осадки из кадра. В этот момент дождь за иллюминатором тоже скрыт. Удаление ванильной воды внутри подводной геометрии остаётся отдельной задачей визуализации.

## Испытание с двумя клиентами

Испытательный мод в `src/smoke` и `src/smokeClient` запускает сценарий на выделенном сервере и в двух полноценных клиентах Minecraft. Этот код исключён из JAR для игроков. В испытании используются два самостоятельных соединения и настоящие локальные клавиши игрового клиента, от которых формируются штатные пакеты Naval Engineering.

1. Из корня проекта выполните `gradlew.bat smokeClientClasses`. Укажите в `build/deck-server/eula.txt` своё согласие на тестовый запуск.
2. Подготовьте `build/deck-server/server.properties`. Значения приведены ниже. Смените имя карты для каждого прогона, чтобы стартовый бассейн был чистым.
3. Запустите `gradlew.bat runDeckServer`. После сообщения о готовности в двух отдельных терминалах запустите `gradlew.bat runDeckPilot` и `gradlew.bat runDeckWalker`.
4. Итог каждого процесса записывается в `deck-result.txt` его папки `build/deck-*`. Клиенты пишут снимки в `screenshots`. Сценарий завершает процессы после результата. Отчёт содержит число замеров, переходы между уровнями, движение после освобождения штурвала и измеренную ошибку положения.

```properties
server-ip=127.0.0.1
server-port=25579
online-mode=false
enforce-secure-profile=false
level-name=local-deck-smoke
level-type=minecraft:flat
generator-settings={"biome":"minecraft:ocean","layers":[{"block":"minecraft:bedrock","height":1},{"block":"minecraft:stone","height":8},{"block":"minecraft:water","height":35}]}
view-distance=5
simulation-distance=5
gamemode=creative
difficulty=peaceful
```

Для автоматического входа запишите `onboardAccessibility:false`, `tutorialStep:none`, `lang:en_us`, `pauseOnLostFocus:false` в `options.txt` обоих испытательных клиентов до запуска. Искусственные потери пакетов и большой RTT в этом сценарии не включены.
